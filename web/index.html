    How it works

    zkTLS turns the HTTPS response x.com sends you into a proof that anyone can check

    1. 01

      Request

      Your browser asks this app's server to sign a proof request for the X template. The Primus app secret never leaves the server

    2. 02

      Prove

      The Primus extension loads api.x.com/1.1/account/settings.json with a Primus attestor and proves only the screen_name field

    3. 03

      Verify

      XWalletRegistry asks the Primus verifier to check the attestor signature, then applies its own rules before saving the link

    What the contract checks

    Signed by a trusted Primus attestorforged or edited proofs
    Proof was made for the sending walletsomeone reusing your proof
    Proof is less than an hour oldold proofs replayed later
    Data came from the X settings API, field screen_nameproofs from other sites or templates

    Newer than the last proof for that handlea previous owner taking a handle back

    Questions

    Does this app see my X password or cookies?

    No. The Primus extension talks to x.com in your browser. The proof that ends up onchain carries your handle and nothing else from your account: no headers, no cookies, no other fields

    Why do I need the Primus extension?

    It runs the zkTLS session with the Primus attestor, so the attestor can sign that the handle really came from x.com without seeing your login. Proofs work in desktop Chrome or Edge

    Can someone else claim my handle?

    Only with a fresh proof from a logged in session of that X account. If an account changes hands, the newest proof wins and an older proof cannot undo it

    What does it cost?

    One transaction. On the test network the gas is paid with free test tokens

    Is HandleSeal an official Primus product?

    No. HandleSeal is a community project built on the public Primus zkTLS SDK and contracts. The code is open source
